# Suihan-shu 个人主页后续操作指南

本文档用于记录网站内容的日常添加、修改、预览和发布流程。

最后更新：2026-07-16

## 1. 当前网站信息

- GitHub 仓库：Suihan-shu/MyPage-suihan
- 默认分支：main
- 网站地址：https://suihan-shu.github.io/MyPage-suihan/
- 本地预览地址：http://localhost:8040
- 发布方式：推送到 main 后，由 .github/workflows/pages.yml 自动构建并发布

当前网站是中文单语界面，英文页面和双语切换依赖已从源码中移除，博客与课程模块也已删除。大多数内容只需要修改 Markdown 或 YAML 文件，不需要修改 Liquid 模板、JavaScript 或 Sass。

当前公开导航包含：

1. 关于
2. 代码库
3. 简历
4. 书籍与电影
5. 旅行日志

博客、课程、文章系列和 RSS 已不再构建，访问 `/blog/`、`/courses/`、`/series/` 或 `/feed.xml` 会返回 404。它们不是“暂时隐藏”，对应页面、数据、模板、样式和脚本已经从源码中删除。

## 2. 两种操作方式

### 2.1 直接在 GitHub 网页上修改

适合修改文字、简历、仓库列表、书籍电影和旅行日志数据。

1. 打开仓库：https://github.com/Suihan-shu/MyPage-suihan
2. 切换到 main 分支。
3. 找到目标文件，点击右上角铅笔图标。
4. 修改文件内容。
5. 在页面底部填写提交说明，例如 Add a travel entry。
6. 点击 Commit changes。
7. 打开仓库的 Actions 页面，确认 Deploy Jekyll site to GitHub Pages 运行成功。

不要直接编辑 _site/。它是构建产物，会被自动重新生成。

### 2.2 在本地修改并预览

建议重新克隆仓库到一个新目录：

    gh repo clone Suihan-shu/MyPage-suihan
    cd MyPage-suihan
    git pull --ff-only origin main
    docker compose up

然后打开 http://localhost:8040。

本地修改完成后，运行检查：

    powershell -ExecutionPolicy Bypass -File scripts/validate_structure.ps1
    docker compose run --rm jekyll bash -c "bundle exec jekyll build --config _config.yml --trace"

确认无误后提交并推送到 main：

    git add <修改过的文件>
    git commit -m "Update homepage content"
    git push origin main

如果一次添加了数据文件和图片，要把两者都加入提交。例如：

    git add _data/travel.yml assets/img/travel/hangzhou-2026-01.jpg
    git commit -m "Add Hangzhou travel entry"
    git push origin main

当前桌面旧项目目录的 .git 文件夹受系统权限限制。如果本地出现 not a git repository 或无法写入 .git，请使用上面的重新克隆方式，不要删除或重置现有文件。

## 4. 修改首页和个人简介

首页内容编辑 `_pages/about.md`。英文页面文件已经从源码中删除。

文件上方的三条短横线之间是页面配置，最后一组短横线之后是正文。例如：

    ---
    layout: about
    title: 关于
    lang: zh
    permalink: /
    display_name: 何岁寒
    subtitle: 保持好奇，持续学习与创造。
    ---

    这里填写你的中文个人简介，可以使用 Markdown。

页面使用 `lang: zh`；当前站点没有语言切换按钮，也不需要维护英文配对页面。

头像文件放在 `assets/img/profile.jpg`。如果更换文件，最好继续使用这个文件名；如果要改文件名，需要同步修改 `_pages/about.md` 中的 `profile.image`。

## 5. 填写中文简历

编辑 `_data/cv.yml`。当前简历保留以下模块：

- 联系方式
- 个人简介
- 项目经历
- 教育经历
- 获奖情况
- 专业技能
- 语言能力
- 兴趣爱好

### 5.1 中文简历示例

    cv:
      name: 何岁寒
      label: 学生 / 开发者
      email: hesuihan95@gmail.com
      phone:
      location: 中国
      website: https://suihan-shu.github.io/MyPage-suihan/
      summary: |
        这里填写个人简介，可以写成一到三句话。

      sections:
        项目经历:
          - company: 项目名称
            position: 项目职责
            start_date: 2024
            end_date: 2025
            location: 地点
            summary: 项目简介
            highlights:
              - 负责的工作内容
              - 项目成果

        教育经历:
          - institution: 学校名称
            area: 专业方向
            degree: 学位
            start_date: 2021
            end_date: 2025
            location: 地点
            highlights:
              - 课程、研究方向或成绩

        获奖情况:
          - title: 奖项名称
            awarder: 颁发单位
            date: 2025
            summary: 奖项说明

        专业技能:
          - name: 编程语言
            level: 熟悉
            keywords:
              - Python
              - C#

        语言能力:
          - name: 中文
            summary: 母语

        兴趣爱好:
          - name: 阅读
            keywords:
              - 技术书籍
              - 科普作品

空字段可以保留为空。YAML 对缩进非常敏感，只使用空格，不要使用 Tab。

### 5.2 更换简历 PDF

当前简历页的 PDF 地址在 `_pages/cv.md` 中配置：

    cv_pdf: /assets/pdf/CV.pdf

最简单的更换方式是把新 PDF 命名为 `CV.pdf`，覆盖 `assets/pdf/CV.pdf`，这样不需要修改页面配置。请确认上传的是最终公开版本，并提前删除手机号、住址、证件号码等不希望公开的信息。

如果使用不同文件名，例如 `Suihan-shu-CV.pdf`，需要同时修改 `_pages/cv.md`：

    cv_pdf: /assets/pdf/Suihan-shu-CV.pdf

文件名区分大小写；修改后应点击简历页面上的 PDF 按钮，确认能正常打开。

## 6. 添加旅行日志

旅行日志数据文件是 `_data/travel.yml`，照片放到 `assets/img/travel/`。添加记录时保留文件顶部已有的 `password`，只编辑 `entries`；如需改密码，再单独修改 `password` 的值。

    password: "保留当前密码或填写新密码"
    entries:
      - id: trip-2026-07
        date: 2026-07-16
        time: "10:30"
        location: 北京 · 颐和园
        title: 夏日午后
        text: 写几句这次旅行的感受。
        photos:
          - file: /assets/img/travel/summer-palace.jpg
            alt: 颐和园
            caption: 难忘的午后

注意事项：

- id 必须唯一，建议使用 trip-年份-月份 格式。
- 日期使用 YYYY-MM-DD。
- 图片路径使用网站路径 /assets/img/travel/文件名.jpg，不要写 Windows 路径。
- `location`、`title`、`text`、`alt` 和 `caption` 直接填写中文。
- photos 可以放多张照片。
- 没有照片时可以写 `photos: []`，也可以省略 photos。
- 建议每次旅行建立独立照片命名，例如 `hangzhou-2026-01.jpg`、`hangzhou-2026-02.jpg`。
- 当前密码是前端比较方式，密码和旅行数据会出现在生成的网页源码中，不是真正的访问控制。不要把身份证、住址、行程安全信息等敏感内容放进去。

## 7. 添加书籍和电影

当前“书籍与电影”页面使用卡片展示元数据。每一本书或每一部电影对应一个 Markdown 文件；正文暂时不会显示在卡片上。

### 7.1 添加书籍

1. 把合法使用的封面放到 `assets/img/media/books/`。
2. 在 `_books/` 新建一个 Markdown 文件，例如 `_books/to-live.md`。
3. 填写以下内容：

       ---
       title: 活着
       creator: 余华
       year: 1993
       started: 2026-07-01
       rating: 5
       status: finished
       cover: /assets/img/media/books/to-live.jpg
       external_url:
       ---

字段说明：

- `title`：书名。
- `creator`：作者。
- `year`：出版年份。
- `started`：开始阅读日期，用于书籍排序，建议填写 `YYYY-MM-DD`。
- `rating`：1 到 5 分。
- `status`：推荐使用 `reading`、`finished`、`queued`、`paused` 或 `abandoned`。
- `cover`：封面的网站路径；没有封面时删除该行或留空，页面会显示占位图。
- `external_url`：可选；填写合法的外部介绍页面后，点击卡片会打开该链接。

### 7.2 添加电影

1. 把合法使用的封面放到 `assets/img/media/movies/`。
2. 在 `_movies/` 新建一个 Markdown 文件，例如 `_movies/farewell-my-concubine.md`。
3. 填写以下内容：

       ---
       title: 霸王别姬
       creator: 陈凯歌
       year: 1993
       watched_on: 2026-07-16
       rating: 5
       status: watched
       cover: /assets/img/media/movies/farewell-my-concubine.jpg
       external_url:
       ---

电影使用 `creator` 填写导演，使用 `watched_on` 进行排序。`status` 推荐使用 `watching`、`watched`、`watchlist`、`paused` 或 `abandoned`。

### 7.3 封面版权与路径

- 只使用自己拍摄、已获得授权、公共领域或明确允许使用的封面。
- 图片文件名尽量使用小写英文、数字和短横线。
- Markdown 中的路径必须和仓库里的文件名完全一致，包括大小写和扩展名。
- 暂时没有合法封面时，可以不填写 `cover`，不要随意复制搜索引擎中的图片。

## 8. 更新仓库展示

编辑 _data/repositories.yml：

    github_repos:
      - name: Suihan-shu/HomestayManager
        platform: github
        tags:
          - C#

      - name: Suihan-shu/新的仓库名
        platform: github
        tags:
          - Personal

name 必须使用准确的 用户名/仓库名。仓库改名后，记得同步修改这里；如果是主页仓库改名，还要同步检查 _config.yml 的 baseurl。

仓库卡片的名称、描述、语言和统计信息由 GitHub 数据动态生成，因此修改 `_data/repositories.yml` 后不需要手动填写仓库描述。若刚改名后仍显示旧内容，先确认新仓库地址可以访问，再等待 GitHub 或卡片服务缓存更新。

## 10. 图片和文件规范

- 文件名尽量使用英文、数字和短横线，例如 west-lake-01.jpg。
- 不要在 Markdown 或 YAML 中使用 C:\Users\... 这类本机路径。
- 图片引用使用 /assets/img/... 或 assets/img/...，具体以所在模板的示例为准。
- 单个文件不要超过 GitHub 的 100 MB 限制。
- 不要上传 API Key、密码文件、身份证、未公开联系方式或其他秘密信息。
- 旅行日志密码虽然已设置，但它属于前端代码的一部分，不能当作真正的密码保护。
- 不要重新创建 `_posts/`、`_series/`、`_pages/courses/`、`_pages/blog.md` 或 `_data/course_resources.yml`；博客与课程模块的模板和样式已经删除，仅添加这些文件不会恢复功能。
- 不要提交 `_site/`、`.jekyll-cache/`、`output/` 或 `assets/rendercv/rendercv_output/`，它们是构建或本地输出目录。

## 11. 发布和检查流程

### 本地检查

    powershell -ExecutionPolicy Bypass -File scripts/validate_structure.ps1
    docker compose run --rm jekyll bash -c "bundle exec jekyll build --config _config.yml --trace"

### GitHub 检查

1. 推送到 main。
2. 打开仓库的 Actions 页面。
3. 查看 Deploy Jekyll site to GitHub Pages。
4. 确认 build 和 deploy 两个任务都是绿色。
5. 访问 https://suihan-shu.github.io/MyPage-suihan/。
6. 如果浏览器仍显示旧内容，使用 Ctrl + F5 强制刷新。

一次完整发布应同时满足：Git 提交成功、`main` 推送成功、Actions 构建成功、线上页面检查正常。只看到本地预览更新，并不代表网站已经发布。

当前项目使用 Actions 发布，不建议使用旧的 scripts/deploy.ps1。该脚本是早期 gh-pages 工作流遗留文件，与当前 main + GitHub Actions 发布方式不同。

## 12. 常见问题

### 页面出现 404

检查以下内容：

1. 仓库名称是否已经改变。
2. _config.yml 中的 baseurl 是否与仓库名一致。
3. Settings → Pages 是否使用 GitHub Actions。
4. Actions 中最近一次构建是否成功。

### 图片不显示

检查文件是否真的提交到仓库、文件名大小写是否一致、引用路径是否以 /assets/ 开头，以及是否误用了 Windows 本机路径。

### YAML 构建失败

优先检查：

- 是否混用了 Tab 和空格；
- 冒号后是否有空格；
- 列表项 - 是否对齐；
- 日期、字符串中是否包含未转义的特殊字符；
- 中文字段是否缺少必要内容。

### 修改后网站没有更新

先确认提交目标是 main，再查看 Actions 日志。构建成功后通常需要等待一小段时间，随后用无痕窗口或 Ctrl + F5 重新访问。

### 博客或课程地址显示 404

这是当前设计，不是部署故障。博客、课程、文章系列和 RSS 已从源码中删除；`/blog/`、`/courses/`、`/series/` 和 `/feed.xml` 应当返回 404。如果未来重新需要这些功能，需要重新实现页面、数据、布局、样式、搜索和导航，不能只添加一个 Markdown 文件。

## 13. 推荐的日常习惯

1. 一次只修改一个模块。
2. 修改前先备份 YAML 文件。
3. 每次提交使用清晰的提交说明，例如 Add Hangzhou travel entry。
4. 新增内容统一使用中文，并保持页面标题、摘要和正文用词一致。
5. 先在本地预览，再推送到 GitHub。
6. 每次发布后检查首页、导航、仓库页、简历页和旅行日志页。

如果不确定应该改哪个文件，直接描述你想添加的内容即可，例如“添加一条杭州旅行记录”或“填写简历中的项目经历”，无需自己修改模板。
